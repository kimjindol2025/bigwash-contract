# Phase 0 검증 실행 런북

작성일: 2026-07-16
대상 상품: 대한이엔지 장비 안심관리 90일 파일럿

> **보류 (2026-07-16)**: 이 런북의 실행은 건너뛰기로 결정됨 — `01-product-payment-marketing-plan.md`
> 13장 참조. 업계 표준 A/S 패턴을 가정하고 Phase 1 구현으로 바로 진행한다. 이 문서와
> `docs/templates/*.csv`는 나중에 실제 데이터로 가정을 재검증하고 싶을 때 그대로 쓴다.

## 목적

앱을 만들기 전에 다음 네 가지를 증거로 확인한다.

1. 기존 고객에게 반복되는 장비관리 문제가 실제로 있다.
2. 고객이 문제 해결에 9만 9천 원을 실제로 지불한다.
3. 대한이엔지 담당자가 매일 기록할 최소 정보가 합의된다.
4. 파일럿과 연간 상품에 양의 공헌이익이 남는다.

이 단계에서는 BigWash의 스키마, 화면, API를 수정하지 않는다. 실제 고객 개인정보와 원본
카카오톡·통화 자료도 Git 저장소에 커밋하지 않는다.

  - 대표·정산담당: 출장·인건비·점검 원가와 상품별 공헌이익 계산

## 개인정보와 증거 보관

- 저장소의 CSV 파일은 빈 템플릿이다.
- 실제 기록에는 고객 이름·전화번호·주소 대신 `C-001`, `SITE-001` 같은 별칭을 쓴다.
- 이름·연락처와 별칭의 대응표는 대한이엔지의 접근 제한 문서에 별도로 보관한다.
- 원본 통화·카카오톡·계약·입금 증빙은 링크나 내부 문서번호만 기록하고 저장소에 복사하지 않는다.
- 인터뷰 녹음은 사전 동의를 받은 경우에만 보관한다.

## 실행 일정

### T — 착수

- 제품책임자가 T 날짜와 실제 담당자를 확정한다.
- 네 템플릿을 접근 제한된 스프레드시트로 복사한다.
- `gate-scorecard.csv`에 담당자·기한을 입력한다.

### T+2 — 최근 A/S 20건 분석

- `as-cases-template.csv` 형식으로 최근 건부터 20건을 기록한다.
- 장비 식별 실패, 상태 확인 재문의, 처리 지연, 기록 누락을 건별로 표시한다.
- 추측하지 않고 원본 통화·메시지·장부에서 확인되는 사실만 적는다.

완료 조건:

- 서로 다른 실제 A/S 20건
- 각 행에 증거 참조 또는 `증거 없음` 표시
- 반복되는 문제 상위 3개와 발생 건수 집계

### T+3 — 내부 담당자 2명 인터뷰

- 접수부터 완료까지 실제 순서를 한 명씩 따로 듣는다.
- 두 사람 모두에게 “매일 반드시 기록할 수 있는 필드”와 “절대 입력하지 않을 필드”를 묻는다.
- 답이 다르면 제품책임자가 공통 최소 필드만 남긴다.

완료 조건:

- 현재 업무 흐름 한 장
- 최소 필드 목록
- 필드별 입력 담당자와 입력 시점

### T+5 — 기존 고객 5명 확인

- `customer-interviews-template.csv`를 사용한다.
- 기능을 설명하기 전에 최근 장비 문제와 현재 해결 방식을 묻는다.
- 인터뷰 마지막에만 90일 9만 9천 원 제안을 제시한다.
- “좋다”는 반응과 “결제한다”는 약속을 구분한다.

완료 조건:

- 서로 다른 고객 5명
- 문제 인정 여부와 가장 중요한 결과 기록
- 가격 제안에 대한 결제·거절·조건부 답변 기록

### T+6 — 수익성 계산

- `unit-economics-template.csv`에 9만 9천 원, 36만 원, 79만 원 상품을 각각 계산한다.
- 대표 또는 정산담당이 출장비, 이동시간, 기술자 시간당 원가를 확인한다.
- 매몰된 개발비가 아니라 고객 한 곳이 추가될 때 늘어나는 변동비를 우선 계산한다.

공식:

```text
총변동비 = 연락 인건비 + 관리 인건비 + 원격지원 인건비
         + 현장 기술자 인건비 + 이동비 + 포함 부품비 + 결제수수료

공헌이익 = 판매가격 - 총변동비
공헌이익률 = 공헌이익 / 판매가격
```

완료 조건:

- 세 상품 모두 계산 근거가 있음
- 포함 서비스와 별도 청구 항목이 구분됨
- 공헌이익이 음수인 상품은 가격 또는 범위를 수정함

### T+10 — 수동 유료 파일럿

- `pilot-tracker-template.csv`를 사용한다.
- 앱 없이 스프레드시트와 카카오톡으로 서비스를 제공한다.
- 무료 체험, 호의적 답변, 구두 약속은 유료 파일럿으로 계산하지 않는다.
- 계좌 입금 또는 기존 결제 절차로 9만 9천 원이 확인돼야 한다.

완료 조건:

- 실제 결제 1건
- 90일 제공 범위와 제외사항에 대한 고객 동의
- 환불 조건과 출장비·부품비 별도 여부 안내

## Go/No-Go 판정

T+10 이후 제품책임자가 `gate-scorecard.csv`를 검토한다.

Go는 다음 네 조건을 모두 충족한 경우에만 선언한다.

- 고객 5명 중 최소 3명이 같은 핵심 문제를 인정했다.
- 최소 1명이 9만 9천 원을 실제로 결제했다.
- 내부 담당자가 매일 기록할 최소 필드와 책임자가 확정됐다.
- 9만 9천 원, 36만 원, 79만 원 상품 모두 공헌이익이 0보다 크다.

하나라도 실패하면 No-Go다. 실패 이유를 다음 중 하나로 분류한다.

- 대상 고객이 다름
- 문제가 충분히 크지 않음
- 제안 결과가 매력적이지 않음
- 가격·서비스 범위가 맞지 않음
- 내부 운영비가 너무 큼

두 번째 사이클에서도 게이트를 통과하지 못하면 기능 개발을 시작하지 않고 문제 정의를 다시
작성한다.
