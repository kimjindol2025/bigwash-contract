# 고객관리 모듈 — 전체 페이지 트리 (v2)

작성일: 2026-07-20 (v1: 2026-07-19)

> 이 문서는 `05-customer-management-design.md`(v2, 필드·데이터모델)를
> **화면 구조(정보 구조/IA)** 수준으로 배치한 것이다. 필드 정의·상태값·API·DB
> 갭 분석은 `05번` 문서 32장이 정본이고 여기서 재정의하지 않는다.
> v1 대비 페이지 트리가 13개 노드 → **9개 좌측 메뉴**로, `05번` 문서 §2의
> 구조로 교체됐다. 상담은 이 트리에 없다 — `05번` 문서 14장에 따라 별도
> "상담·문의" 모듈 소관이고, 고객 상세의 "상담" 탭에서 필터링만 한다.

## 0. 범위

이 문서가 다루는 것은 **고객관리 모듈 하나**다. 회사 전체 관리시스템에서
고객관리가 차지하는 위치는 `docs/07-company-system-menu.md`를 따른다.

```text
고객관리는 판매·견적·계약·출장·상담을 자기 안에서 새로 구현하지 않는다.
각 모듈의 기록을 고객 기준으로 모아서 보여줄 뿐이다.
```

## 1. 전체 페이지 트리 (13개)

```text
고객관리
│
├─ 1. 고객 대시보드
├─ 2. 고객 목록
├─ 3. 신규 고객 등록
├─ 4. 고객 상세
├─ 5. 고객 현장
├─ 6. 고객 장비
├─ 7. 고객 담당자
├─ 8. 고객 할 일
├─ 9. 사후관리
├─ 10. 중복 고객 관리
├─ 11. 고객 분류
├─ 12. 고객 가져오기·내보내기
└─ 13. 고객관리 설정
```

## 2. 좌측 메뉴 (9개, 실제 화면 기준)

```text
고객관리
├─ 고객 대시보드
├─ 전체 고객
├─ 신규 고객
├─ 고객 현장
├─ 고객 장비
├─ 고객 할 일
├─ 사후관리
└─ 설정
```

13개 노드 중 "4. 고객 상세"는 목록에서 행을 눌러 들어가는 상세 화면이라
메뉴가 아니다. "10. 중복 고객 관리"·"11. 고객 분류"·"12. 가져오기·내보내기"는
"설정" 또는 "전체 고객"의 필터·부가 기능으로 흡수한다(v1과 같은 압축 원칙).

## 3. 각 페이지 요약 (상세 필드는 `05번` 문서 참조)

### 3.1 고객 대시보드 (`05번` 3장)

```text
오늘 연락할 고객 / 미처리 문의 고객 / 견적 보내야 하는 고객 /
출장 접수 필요 고객 / 출장 후 확인 필요 고객 / 미수금 고객 /
연간관리 만료 예정 / 장기 미거래 고객 / 최근 등록 고객 / 최근 활동 고객
```
상단: `[고객 검색] [신규 고객] [상담 기록] [견적 작성] [출장 접수] [문자 보내기]`

### 3.2 전체 고객 (`05번` 4장)

목록 표시(고객번호·고객명·사업장명·연락처·지역·유형·상태·최근연락일·다음관리일·
진행업무·미수금·연간관리) + 필터(12종) + 검색(11개 항목, 전화번호 부분·정규화
검색 포함).

### 3.3 신규 고객 (`05번` 5장)

빠른 등록(4개 필수 필드, 10초 목표) + 상세 등록(기본정보/사업자정보/
주소정보/관리정보 4구획).

### 3.4 고객 상세 (`05번` 8~25장, 메뉴 아님 — 목록에서 진입)

```text
상단 요약 → 빠른 실행 → 경고·알림 → 진행 중 업무 → 상세 탭
탭: 개요·타임라인·기본정보·담당자·현장·장비·상담·판매·견적·계약·
    출장·연간관리·금액·메시지·사진문서·사후관리·변경이력
```

### 3.5 고객 현장 (`05번` 12장)

고객 1:N 현장, 각 현장에 주소·담당자·주차·출입·설치장비·사진.

### 3.6 고객 장비 (`05번` 13장)

장비 정보 + 7단계 상태 + 이력(설치·출장·수리·부품교체·점검).

### 3.7 고객 할 일 (`05번` 24장)

고객·업무내용·관련기록·예정일·중요도·상태(예정/진행중/완료/지연/취소).

### 3.8 사후관리 (`05번` 23장)

10가지 유형, 예정일·목적·연락방법·처리내용·고객반응·다음관리일.

### 3.9 설정 (`05번` 언급 없음, 트리 13번 "고객관리 설정" 흡수)

고객 유형·상태·태그·등급 기준, 중복 판정 기준, 가져오기·내보내기 양식.

## 4. 핵심 구조

```text
고객 목록
   ↓
고객 상세
   ├─ 상담(다른 모듈 데이터, customer_id 필터)
   ├─ 현장 / 장비
   ├─ 판매 / 견적 / 계약(다른 모듈 데이터)
   ├─ 출장 / 연간관리(다른 모듈 데이터)
   ├─ 금액(회계 모듈 데이터)
   └─ 사후관리
```

고객관리는 여러 페이지를 따로 만드는 게 아니라 **고객 상세 페이지를
중심으로 회사의 모든 업무가 가지처럼 연결되는 구조**다 — v1과 동일한
결론, 이번엔 "상담"까지 포함해 다른 모듈 데이터를 끌어오는 범위가 더
명확해졌다.
