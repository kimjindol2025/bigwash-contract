## 1. 고객관리의 역할

고객관리의 목적은 고객 정보를 많이 저장하는 것이 아니다. 핵심은 네 가지다.

1. 전화가 왔을 때 누구인지 바로 찾는다.
2. 이 고객과 과거에 무슨 일이 있었는지 확인한다.
3. 지금 진행 중인 일이 무엇인지 안다.
4. 다음에 무엇을 해야 하는지 놓치지 않는다.

고객관리는 아래 모든 모듈의 중심 연결점이다.

```text
고객
├─ 상담
├─ 상품 판매
├─ 견적
├─ 계약
├─ 출장서비스
├─ 연간관리
├─ 입금·미수금
├─ 문자·카카오
├─ 사진·문서
└─ 사후관리
```

다만 고객관리 안에서 이 기능들을 다시 구현하지 않는다.

```text
고객관리     → 고객 기준으로 연결 기록을 보여준다.
견적관리     → 실제 견적을 작성하고 상태를 관리한다.
출장서비스   → 실제 출장 접수와 작업을 처리한다.
```

이 원칙은 `docs/06-customer-management-page-tree.md` §0과 `docs/07-company-system-menu.md`
§0가 이미 "고객관리는 다른 모듈을 새로 구현하지 않는다"고 못박은 것과 동일하다.

## 2. 고객관리 전체 페이지 구조

```text
고객관리
│
├─ 1. 고객 대시보드
├─ 2. 고객 목록
├─ 3. 신규 고객 등록
├─ 4. 고객 상세
├─ 5. 고객 현장
├─ 6. 고객 장비
├─ 7. 고객 담당자
├─ 8. 고객 할 일
├─ 9. 사후관리
├─ 10. 중복 고객 관리
├─ 11. 고객 분류
├─ 12. 고객 가져오기·내보내기
└─ 13. 고객관리 설정
```

실제 좌측 메뉴는 더 단순하게 둔다.

```text
고객관리
├─ 고객 대시보드
├─ 전체 고객
├─ 신규 고객
├─ 고객 현장
├─ 고객 장비
├─ 고객 할 일
├─ 사후관리
└─ 설정
```

`docs/06번` 문서의 페이지 트리(13개 노드 → 9개 좌측 메뉴)는 이 새 구조로
갱신한다 — 별도 커밋에서 `docs/06`을 이 장 기준으로 다시 쓴다.

## 3. 고객 대시보드

고객관리 첫 화면은 통계보다 업무 중심이어야 한다.

### 표시 항목

```text
오늘 연락할 고객
미처리 문의 고객
견적을 보내야 하는 고객
출장 접수가 필요한 고객
출장 후 확인이 필요한 고객
미수금 고객
연간관리 만료 예정 고객
장기간 거래가 없는 고객
최근 등록 고객
최근 활동 고객
```

### 상단 빠른 실행

```text
[고객 검색] [신규 고객] [상담 기록] [견적 작성] [출장 접수] [문자 보내기]
```

### 카드 예시

```text
오늘 연락할 고객: 4명
미처리 상담: 3건
미수금 고객: 5명
사후관리 예정: 2명
연간관리 만료 예정: 1명
```

> 고객 대시보드는 고객 통계를 보여주는 화면이 아니라, 오늘 고객과 관련해
> 해야 할 일을 보여주는 화면이다.

## 4. 고객 목록 페이지

고객 전체를 찾고 분류하는 화면이다.

### 목록 표시 항목

| 항목 | 설명 |
|---|---|
| 고객번호 | 내부 관리번호 |
| 고객명 | 개인 또는 대표자명 |
| 사업장명 | 회사·매장·현장명 |
| 대표 연락처 | 전화번호 |
| 지역 | 출장 판단용 |
| 고객 유형 | 개인·사업자·거래처 |
| 고객 상태 | 잠재·거래·휴면 등 |
| 최근 연락일 | 마지막 상담 또는 메시지 |
| 다음 관리일 | 다시 연락할 날짜 |
| 진행 업무 | 견적·계약·출장 건수 |
| 미수금 | 받을 금액 |
| 연간관리 | 가입 여부 |

### 필터

```text
전체 고객 / 신규 고객 / 잠재 고객 / 상담 중 / 거래 고객 / 서비스 고객 /
연간관리 고객 / 미수금 고객 / 휴면 고객 / 거래 종료 / 지역별 / 태그별
```

### 검색 항목

```text
고객명 / 사업장명 / 전화번호 / 주소 / 대표자명 / 담당자명 /
장비명 / 모델명 / 시리얼번호 / 상담 내용 / 메모
```

전화번호는 하이픈 유무·자릿수에 상관없이 검색되어야 한다 — `01012345678`,
`010-1234-5678`, `1234`, `5678`이 모두 같은 고객을 찾을 수 있어야 한다.

> 다음 단계에서 이 문서 전체 중 **고객 목록 페이지 하나만** 화면 단위로
> 먼저 확정한다(사용자 지정 순서). 32장에서 이 페이지의 현재 구현 상태를
> 확인할 것.

## 5. 신규 고객 등록

전화받는 중에도 등록 가능해야 하므로 두 가지 방식으로 나눈다.

### 5.1 빠른 등록

필수: 고객명 또는 사업장명, 전화번호, 지역 또는 주소, 간단한 문의 내용.
선택: 고객 유형, 다음 조치, 다음 연락일.

버튼: `[저장] [저장 후 상담 작성] [저장 후 견적 작성] [저장 후 출장 접수]`

> 신규 고객을 10초 안에 등록할 수 있어야 한다.

### 5.2 상세 등록

거래가 진행될 때 작성한다.

- **기본정보**: 고객번호, 고객명, 사업장명, 대표자명, 대표 연락처, 이메일,
  고객 유형, 고객 상태, 등록 경로, 등록일
- **사업자정보**: 사업자등록번호, 법인등록번호, 업태, 종목, 세금계산서
  이메일, 사업자등록증 첨부
- **주소정보**: 기본 주소, 상세 주소, 우편번호, 배송 주소, 청구 주소, 현장
  주소, 지도 좌표
- **관리정보**: 고객 등급, 담당자, 관심 상품, 주요 장비, 거래 시작일, 최근
  거래일, 다음 관리일, 내부 메모, 주의사항

## 6. 고객 유형

```text
개인 고객 / 사업자 고객 / 법인 고객 / 공공기관 / 거래처 / 협력업체 /
잠재 고객 / 기타
```

대한이엔지 기준 세부 업종: 셀프세차장, 손세차장, 주유소, 정비소, 공장, 빌딩,
관공서, 학교, 장비업체, 부품업체, 기타.

**고객 유형과 고객 상태는 구분한다**:

```text
고객 유형 = 누구인가       예: 사업자 고객
고객 상태 = 현재 관계가 어떤가  예: 견적 진행 중
```

## 7. 고객 상태

```text
신규 / 잠재 / 상담 중 / 견적 진행 / 계약 진행 / 거래 고객 /
서비스 고객 / 연간관리 고객 / 휴면 / 관리주의 / 거래 종료
```

권장 흐름: `신규 → 상담 중 → 견적 진행 → 계약 진행 → 거래 고객 →
서비스 고객 → 연간관리 고객`. 모든 고객이 이 순서를 따를 필요는 없다 —
예: 전화 수리 문의 → 신규 → 상담 중 → 출장 접수 → 서비스 고객.

## 8. 고객 상세 페이지

고객관리의 핵심 화면이다.

```text
고객 상세
├─ 상단 고객 요약
├─ 빠른 실행 버튼
├─ 경고·알림
├─ 진행 중 업무
└─ 상세 탭
```

### 8.1 상단 고객 요약

고객명, 사업장명, 대표 연락처, 지역, 고객 상태, 고객 등급, 최근 연락일,
다음 관리일, 미수금, 연간관리 여부.

```text
김포 ○○셀프세차장
거래 고객 · 연간관리 가입
010-1234-5678
경기도 김포시
최근 연락: 2026-07-18
다음 관리: 2026-07-25
미수금: 350,000원
```

### 8.2 빠른 실행 버튼

`[전화상담] [문자] [견적] [계약] [출장] [상품판매] [입금등록] [사진등록] [할 일]`

### 8.3 경고·알림

미수금 있음 / 출장 재방문 필요 / 견적 답변 지연 / 연간관리 만료 예정 /
보증기간 종료 예정 / 고객 불만 기록 있음.

### 8.4 고객 상세 탭

```text
개요 / 타임라인 / 기본정보 / 담당자 / 현장 / 장비 / 상담 / 판매 / 견적 /
계약 / 출장 / 연간관리 / 금액 / 메시지 / 사진·문서 / 사후관리 / 변경 이력
```

## 9. 고객 개요 탭

```text
고객 개요
├─ 오늘 해야 할 일
├─ 진행 중인 업무
├─ 최근 상담
├─ 최근 판매
├─ 최근 견적
├─ 최근 출장
├─ 보유 장비
├─ 미수금
├─ 연간관리
└─ 다음 일정
```

진행 중 업무 예: `견적 1건 검토 중 / 출장 1건 방문 예정 / 미수금 350,000원 /
사후관리 1건 예정`.

## 10. 고객 타임라인

```text
2026-07-18  출장 완료
2026-07-17  방문 일정 문자 발송
2026-07-16  전화상담
2026-07-10  고압호스 판매
2026-06-30  견적 발송
2026-06-28  최초 문의
```

대상: 상담·문자·카카오·이메일·판매·견적·계약·출장·입금·미수금·사진·문서·
사후관리·메모·상태 변경.

필터: 전체 / 상담 / 판매 / 견적 / 계약 / 출장 / 금액 / 메시지 / 사진·문서.

구현 원칙(v1과 동일하게 유지): 타임라인 전용 저장 테이블을 새로 만들지
않는다. `customer_id`(또는 `site_id`)를 공통 키로 갖는 여러 테이블을
`UNION`해 시간순으로 조회하는 뷰로 구현한다 — 전용 테이블을 만들면 원본
도메인 테이블과 내용이 이중화된다.

## 11. 고객 담당자

사업자 고객은 여러 담당자가 있을 수 있다.

```text
대표자 / 관리자 / 현장 담당자 / 회계 담당자 / 구매 담당자 / 시설 담당자 / 기타
```

담당자 정보: 이름, 직책, 부서, 휴대전화, 이메일, 담당 역할, 주 연락 담당
여부, 메모, 퇴사·변경 여부.

```text
김대표 / 대표자 / 계약 담당
박과장 / 현장 관리자 / 출장 대응
이대리 / 회계 담당 / 세금계산서
```

**고객 자체와 담당자를 분리한다**: 고객 = ○○셀프세차장, 담당자 = 김대표·
박과장·이대리.

## 12. 고객 현장

한 고객이 여러 현장을 가질 수 있다.

```text
고객
├─ 본점
├─ 2호점
├─ 창고
└─ 신규 공사 현장
```

현장 정보: 현장명, 현장 유형, 주소, 현장 담당자, 연락처, 지도 위치, 주차
방법, 출입 방법, 방문 가능 시간, 설치 장비, 현장 사진, 주의사항.

출장과 계약은 고객뿐 아니라 현장에도 연결한다:
```text
고객: ○○기업 / 현장: 김포 2호점 / 장비: 고압세척기 3번 / 출장: 압력 저하 수리
```

## 13. 고객 장비

### 장비 정보

장비번호, 장비명, 분류, 제조사, 모델명, 시리얼번호, 구매일, 설치일, 설치
현장, 판매 금액, 보증 시작일, 보증 종료일, 현재 상태, 최근 점검일, 다음
점검일.

### 장비 상태

```text
정상 / 점검 필요 / 수리 필요 / 수리 중 / 교체 권장 / 사용 중지 / 폐기
```

### 장비 상세 이력

설치 이력, 출장 이력, 수리 이력, 교체 부품, 소모품 교환, 작업 사진, 매뉴얼,
보증 기록, 점검 예정.

장비를 선택하면 관련 출장 기록만 필터링해서 보여준다.

## 14. 고객 상담 연결

**상담은 독립적인 "상담·문의" 모듈에서 관리한다.** 고객 상세의 상담 탭은
해당 고객 상담만 보여준다.

```text
상담·문의 모듈       → 전체 상담 관리
고객 상세 > 상담     → 이 고객의 상담만 표시
```

> 이 원칙은 `docs/07-company-system-menu.md` §0가 이미 내린 결론과 같다 —
> 최상위 메뉴의 "3. 상담·문의"와 고객관리 하위 상담 화면이 별개 구현이
> 아니라 **같은 데이터를 다른 진입점에서 보여주는 것**이라는 뜻이다.
> 지금 이미 구현된 `consultations` 테이블·API(`POST /care/consultations`
> 등, 32장 참조)는 그대로 "상담·문의 모듈"의 데이터 계층이 되고, 고객
> 상세의 "상담" 탭은 `customer_id`로 필터링해서 보여주면 된다 — 재설계
> 필요 없음.

상담 기록 항목: 상담 일시, 상담 방식, 상담 상대방, 상담 내용, 관련 현장,
관련 장비, 긴급도, 처리 결과, 다음 조치, 다음 연락일, 담당자.

상담 결과: 상담 완료 / 재연락 / 상품 판매 / 견적 작성 / 계약 검토 / 출장
접수 / 불만 처리.

## 27. 고객 삭제와 거래 종료

고객은 쉽게 삭제하면 안 된다.

```text
활성 고객 → 휴면 고객 → 거래 종료 → 보관
```

삭제는 잘못 등록한 고객·테스트 데이터에만 제한한다. 거래 종료 시에도 과거
판매·출장·계약 기록은 유지한다.

## 29. 고객관리 핵심 자동화

**전화가 왔을 때**: 전화번호 검색 → 기존 고객 표시 → 최근 상담 표시 → 보유
장비 표시 → 진행 중 출장 표시 → 미수금 표시 → 상담 기록 시작.

**신규 고객일 때**: 빠른 고객 등록 → 상담 기록 → 다음 조치 선택.

**상담 후**: 상담 저장 → 다시 연락 날짜 생성 또는 견적 생성 또는 출장 접수.

**출장 완료 후**: 출장 완료 → 고객 타임라인 반영 → 금액 연결 → 사진 확인 →
사후관리 생성 → 완료 문자 발송 후보 생성.

**판매 완료 후**: 판매 완료 → 고객 구매 이력 → 장비 등록 → 보증 등록 →
재고 차감 → 사후관리 생성.

## 31. 고객관리 완료 기준

```text
이 고객은 누구인가? / 어디에 있는가? / 누구와 연락해야 하는가? /
무엇을 구매했는가? / 어떤 장비를 사용하고 있는가? / 최근 어떤 문제가 있었는가? /
현재 진행 중인 일이 있는가? / 받을 돈이 남아 있는가? / 다음에 무엇을 해야 하는가?
```

> 고객관리는 고객 정보를 저장하는 주소록이 아니라, 고객과 회사 사이에서
> 발생한 상담·판매·견적·계약·출장·결제·사후관리 기록을 하나의 시간선으로
> 연결하고 다음 행동을 알려주는 회사 운영의 중심 시스템이다.

## 33. 1차 고객 목록 컬럼 확정 (2026-07-20)

4장의 12개 목록 표시 항목을 실제 스키마·1차 범위(30장)와 대조해 사용자와
합의한 결과. **여기서부터는 4장(목표 스펙 원문)이 아니라 1차 구현의 실제
계약(contract)이다** — 다음 단계의 API·UI 설계는 이 절 기준으로 한다.

### 포함 (8개)

| 컬럼 | 소스 | 비고 |
|---|---|---|
| 고객번호 | `customers.id` | 별도 포맷 코드(예: `C-2026-0001`) 없이 DB id 그대로. 필요해지면 나중에 추가 |
| 고객명 | `customers.name` | 기존 그대로 |
| 사업장명 | `sites` LEFT JOIN | 고객의 대표(첫 번째) 현장 이름. 현장이 없으면 빈칸. `customers`에 새 필드 만들지 않음 |
| 대표 연락처 | `customers.phone` | 기존 그대로 |
| 지역 | `customers.address` 파싱 | 저장된 주소 앞부분(시/도)만 잘라 표시. 파싱 실패 시 address 원문 노출. 별도 입력 필드 신설 안 함 |
| 고객 유형 | `customers.customer_type` | 기존 4종(LEAD/CUSTOMER/SERVICE/VENDOR) 그대로. 6장의 8종 세부 유형은 이번 범위 아님 |
| 최근 연락일 | `consultations` 최신 레코드 | customer_id 기준 최신 상담일 |
| 다음 관리일 | `consultations.next_contact_at` | 기존 `list-followups-today` 로직 재사용. `next_followup_at`은 별개 테이블 `customer_followups`의 컬럼이므로 혼동 주의(`phase1-db.fl`) |

### 제외 (4개, 2~3차로 명시적 연기)

| 컬럼 | 이유 |
|---|---|
| 고객 상태(11종, 7장) | `customer_type` 4종만 유지 — 별도 상태 필드는 `customer_status_history`와 함께 2~3차에서 다룬다 |
| 진행 업무 | 견적·계약 건수 집계 — "견적 연결"·"계약 연결" 자체가 30장 3차 항목이라 함께 미룬다 |
| 미수금 | 회계·수금 모듈 없음(30장 3차 "금액 연결") |
| 연간관리 | 이 절이 확정한 것은 "1차 고객 **목록**" 8개 컬럼에서의 제외이며, 연간관리 모듈 자체는 32장 갱신대로 2026-07-21 4~5주차에 구현 완료됐다(고객 **상세** 탭·상단 요약에는 이미 표시됨). 고객 목록 화면에 별도 컬럼으로 노출하는 것만 여전히 2~3차로 연기 |

> 필터·검색 항목(4장)도 같은 원칙으로 좁힌다: 이번 화면은 `customer_type`
> 기준 필터(전체/잠재/거래/서비스/거래처 — 현재 Admin UI 5종과 동일)와
> 이름·전화·주소·메모 검색(현재 `search-customers`와 동일 + 전화번호
> 하이픈 정규화 추가)까지만 포함한다. 12종 필터·11개 검색 항목·태그별
> 필터는 2~3차.
