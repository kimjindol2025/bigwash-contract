# 2026-07-21 WashCare 4주차 CarePlan 백엔드 체크포인트

## 이번 작업

- 현장(`site_id`) 단위 CarePlan 스키마와 조회·가입·수정·취소·갱신 API 6개를 추가했다.
- `TRIAL_90`, `BASIC_360`, `FIELD_790`의 기간, 방문 횟수, 가격 스냅샷 기본값을 고정했다.
- 취소되지 않은 플랜의 기간 중복을 막고, 갱신을 기존 플랜의 `RENEWED` 전환과 신규 플랜 생성을 묶은 트랜잭션으로 처리했다.
- 저장 상태와 서울 시간 기준 파생 만료 상태를 분리하고, 방문 사용 횟수의 절대값 정정을 멱등 API로 제공했다.
- 구현에 맞춰 API 문서, OpenAPI, 실행 가이드와 6주 일정표를 동기화했다.

## 중요한 결정

- CarePlan은 고객이 아니라 설치 현장에 귀속한다.
- 가격은 가입 시점의 정수 원화 스냅샷으로 보존하며 `payment_status`와 PG 연동은 이번 범위에서 제외한다.
- 저장 상태는 `ACTIVE`, `CANCELLED`, `RENEWED`만 사용하고, 기간이 지난 활성 플랜은 응답에서만 `EXPIRED`로 파생한다.
- 방문 사용 횟수는 자동 차감하지 않으며, 5주차 화면에서도 티켓과의 자동 과금·차감 연동을 하지 않는다.

## 검증 기준

- FreeLang 테스트 10종 전체 통과
- CarePlan 날짜·윤년·금액·횟수·중복·취소·갱신·고객 격리 회귀 통과
- 구현과 OpenAPI의 API 라우트 53개 일치 및 YAML 파싱 통과
- 실제 HTTP 요청으로 가입·수정·갱신·400·404 응답 확인
- `git diff --check` 통과
- 운영 DB `db/contracts.sqlite`는 커밋 대상에서 제외

## 다음 작업

5주차에는 CarePlan 관리 화면, 고객 상세의 플랜 요약, 티켓 작성 시 활성 플랜 안내를 구현한다. 이를 위해 먼저 관리자 화면에서 사용할 전역 플랜 목록 계약을 보완하고, 화면 입력의 XSS 방어·모바일 동작·취소 및 갱신 확인 절차를 독립 리뷰한다. 운영 배포와 실제 DB 마이그레이션은 별도 승인 전까지 수행하지 않는다.
