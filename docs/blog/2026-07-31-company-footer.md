존재했다. 이번 체크포인트에는 회사정보 푸터 CSS와 HTML 25줄만 포함했고, 기존
계약관리·보안 게이트·DB·문서·테스트 변경은 포함하지 않았다.

## 검증

- 제공된 회사정보 7개 문자열이 HTML에 모두 존재하는지 검사했다.
- 390×844 Chrome Headless 캡처에서 모바일 푸터의 줄바꿈과 전화 링크 크기를
  확인했다.
- 스테이징된 HTML에서 푸터 CSS가 `</style>` 앞에 있고 푸터 본문이
  `<script>` 앞에 있는지 검사했다.
- `git diff --cached --check`를 통과했다.
- 스테이징 결과가 `src/washcare-admin.html` 25줄 추가뿐인지 확인했다.

## 시행착오와 교정

- 첫 부분 스테이징 패치는 문맥이 없어 CSS와 HTML이 인덱스의 파일 끝에 붙었다.
  `git diff --cached` 검토에서 커밋 전에 발견했고, 작업 파일은 건드리지 않은 채
  스테이징만 해제했다.
- 두 번째 패치에는 HEAD의 정확한 주변 문맥을 넣어 CSS와 HTML이 올바른 위치에
  들어가는 것을 확인했다. 다음 작업자도 미커밋 변경이 많은 파일을 부분
  커밋할 때 무문맥 패치를 사용하지 말고 반드시 스테이징 diff를 검토해야 한다.
- 인증된 운영 HTML을 직접 가져오기 위해 설정 파일을 확인했지만 예상한 위치에
  인증값이 없었다. 실행 환경에서 인증값을 우회 추출하지 않았으며, 검증된 파일을
  읽는 프로세스 재시작과 상태·포트·인증 경계 확인으로 마무리했다.
